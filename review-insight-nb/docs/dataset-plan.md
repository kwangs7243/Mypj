# Dataset Plan

## Purpose

The current 20-row sample dataset is only for pipeline validation. The next phase needs larger and more varied datasets so model comparison is meaningful.

This project will use two dataset types:

1. Controlled synthetic datasets generated inside the project.
2. Real public Korean review datasets added later after checking source, license, and format.

## Korean Summary

현재 20개 샘플 데이터는 파이프라인 검증용이다. 다음 단계에서는 모델 비교가 의미 있으려면 더 크고 다양한 데이터셋이 필요하다.

이 프로젝트에서는 두 종류의 데이터셋을 사용한다.

1. 프로젝트 안에서 생성하는 통제된 synthetic 데이터셋
2. 출처, 라이선스, 형식을 확인한 뒤 추가할 실제 공개 한국어 리뷰 데이터셋

## Important Warning

Synthetic data generated by Codex or templates is useful for testing pipeline behavior, label balance, preprocessing, tokenization, and model comparison code.

It should not be treated as proof of real-world generalization performance.

Real performance claims require a real dataset with documented source and evaluation rules.

Large datasets should not be committed to Git. Store them externally, such as on a USB drive or another local data storage location, and keep only small samples, README files, scripts, and regeneration instructions in the repository.

## 중요한 주의점

Codex나 템플릿으로 생성한 synthetic 데이터는 파이프라인 동작, 라벨 균형, 전처리, 토큰화, 모델 비교 코드 검증에는 유용하다.

하지만 실제 서비스 일반화 성능을 증명하는 데이터로 해석하면 안 된다.

실제 성능을 주장하려면 출처와 평가 규칙이 명확한 실제 데이터셋이 필요하다.

큰 데이터셋은 Git에 커밋하지 않는다. USB나 별도 로컬 데이터 저장소에 보관하고, 저장소에는 작은 샘플, README, 생성 스크립트, 재생성 방법만 남긴다.

## Target Dataset Sizes

Use staged dataset sizes so experiments do not overload a 16GB memory environment.

```text
smoke: 200 rows
quick: 5,000 rows
compare: 20,000 rows
main: 50,000 rows
```

Recommended first generated dataset:

```text
5,000 rows
2,500 positive
2,500 negative
```

Recommended first meaningful comparison dataset:

```text
20,000 rows
10,000 positive
10,000 negative
```

Recommended upper target for traditional ML experiments on this machine:

```text
50,000 rows
25,000 positive
25,000 negative
```

## Dataset Schema

Every dataset should keep this minimum schema:

```text
text,label
```

Allowed labels:

```text
positive
negative
```

Optional columns may exist in raw data, but training scripts should rely on `text` and `label`.

## Git Tracking Rule

- Track folder structure, README files, scripts, and small sample files.
- Ignore large raw/generated/processed/split dataset files.
- If a dataset must be used, document where to place it and which script generates or consumes it.
- If a vocabulary or dictionary is small and intentionally limited, it may be committed with a `_sample` or `_limited` suffix.
- Large tokenizer artifacts such as SentencePiece `.model` and `.vocab` files should stay ignored unless there is a clear reason to version a small limited artifact.

## Git 추적 규칙

- 폴더 구조, README, 스크립트, 작은 샘플 파일은 추적한다.
- 큰 raw/generated/processed/split 데이터셋 파일은 무시한다.
- 데이터셋을 사용해야 한다면 어디에 배치해야 하는지와 어떤 스크립트가 생성/사용하는지 문서화한다.
- 작고 의도적으로 제한된 단어사전은 `_sample` 또는 `_limited` suffix를 붙여 커밋할 수 있다.
- SentencePiece `.model`, `.vocab` 같은 큰 tokenizer artifact는 명확한 이유가 없는 한 Git에서 제외한다.

## Raw vs Processed

Raw/generated datasets may intentionally contain noisy text:

- Korean text
- inconsistent spacing
- numbers
- English words
- punctuation
- repeated expressions
- emojis or symbols

Processed datasets should be generated by explicit preprocessing rules.

Different preprocessing outputs may be saved separately later:

```text
processed/korean_only_5k.csv
processed/morph_tokenized_5k.csv
processed/sentencepiece_5k.csv
```

## Why Keep Noisy Raw Text?

Noisy raw text is useful because later experiments can compare:

- simple Korean-only regex cleaning
- spacing normalization
- Korean morphological analysis
- SentencePiece subword tokenization
- whether English/numbers/symbols help or hurt

The current MVP removes English, numbers, punctuation, emojis, and symbols. Later experiments can decide whether that rule should change.

## 왜 지저분한 원본 텍스트를 남기는가?

지저분한 원본 텍스트를 남겨두면 이후 다음 항목을 비교할 수 있다.

- 단순 한글 전용 정규식 정제
- 공백 정리
- 한국어 형태소 분석
- SentencePiece subword 토큰화
- 영어, 숫자, 기호가 도움이 되는지 방해가 되는지

현재 MVP는 영어, 숫자, 문장부호, 이모지, 기호를 제거한다. 이후 실험에서 이 규칙을 바꿀지 판단한다.

## Dataset Creation Plan

### Step 1. Controlled Generated Dataset

Create a script that generates balanced Korean product review sentences from templates.

The generated dataset should include:

- product/service nouns
- positive and negative sentiment phrases
- delivery, price, quality, usability, customer service, packaging, refund, durability topics
- mild noise such as punctuation, repeated spaces, numbers, and occasional English words

Purpose:

- test preprocessing behavior
- test model comparison scripts
- test tokenizer experiments
- avoid relying on a tiny 20-row sample

### Step 2. Real Dataset Candidate

Later, choose a real Korean review dataset.

Selection criteria:

- Korean text
- binary or convertible sentiment labels
- clear source
- usable license
- manageable size for 16GB memory
- can be converted to `text,label`

### Step 3. Dataset Size Comparison

Use the same preprocessing/model settings and compare:

```text
5k vs 20k vs 50k
```

Goal:

- observe whether more data improves validation performance
- check training time
- check memory behavior
- find a practical dataset size for the project
